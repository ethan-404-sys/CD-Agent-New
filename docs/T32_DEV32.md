# T3.2 Dev-32 单期类别视觉参考

从正式 `query_test.json` 取 `meta.form == 1`、`prompt_mode == "na"` 的单期跨场景参考。K=1，查询和参考均为 512×512。固定种子 321118 按来源分配 7、7、6、6、6 题，依次覆盖 HIUCDMINI_tile512、SECOND、HRMS_SCD、SCSCD7、lsSCD。抽样优先覆盖类名和目标面积档，同一 query identity group 只取一次。三个有最多空真值候选的来源各取一题空真值。清单 `sample.json` 记录原始清单的零基行号、类别、面积档、是否空真值及 GT 路径。

`t32_dev32 prepare` 在输出目录 `inputs/case-XX/` 写入查询双期原始 RGB、单期原始参考、参考二值掩码以及无歧义三联参考视图 `reference-view.jpg`（左：未遮挡原图；中：仅在前景内部半透明绿色着色 + 1px 内边缘，背景与被排除孔洞不压暗、不被外扩轮廓包围；右：纯黑白二值掩码，白=目标类，黑=非目标）。支持 `--manifest` 从官方清单抽样，或 `--reuse-from <已有目录>` 复用固定 32 题清单并刷新三联参考视图。推理仅加载匿名输入。Planner 首轮看到 Query T1、Query T2 和三联参考视图；Verifier 在每次独立核验中看到同一张三联参考视图和查询区域的双期裁块。Python 工具可按需读参考图和掩码数组，二者使用参考场景坐标。

沿用 `loop_json.run_session`、G3 提交门、SAM3 文字分割、SAM 点框提示和 Recorder，并启用三项 P0 修复：（1）三联参考视图与大类语义口径，消除图底反转；（2）`sam3_worker` 同步缓存 SAM3 原生 `semantic_mask_logits` 与 `presence_score`，`segment_text` / `segment_text_pair` 支持 `mode=instance|semantic|fused` 并返回 `presence_score` 与 `semantic_area`，解决遥感 stuff 类空检；（3）开启 `answer_state`、`explicit_answer`（草稿掩码默认 `set_current=false`，须显式 `set_answer` 晋升主答案，状态索引附带各句柄面积/实例数）与 `segment_pair`，同时将单框面积上限放宽至 `big_box_share=0.5`。Planner、Verifier 均直连百炼公共端点，使用 `qwen3.7-flash`。标准配置同时运行 3 个会话，最多 3 个待响应的 Verifier 请求，Planner 最多 30 轮。

`t32_dev32 report` 等 32 张 `prediction.png` 落盘后读取 GT，按 GT 1、0、255 分别记前景、背景、忽略。预测非零为前景。逐题 IoU、F1 在预测与 GT 均空时为 1，Precision、Recall 分母为零时记 0。汇总含微平均、全题宏平均、正例宏平均，以及空真值题的虚警像素总数和空预测数。各题的 `steps.jsonl`、`messages.jsonl`、中间图像/掩码、终止状态及离线指标保存在 `traces/case-XX/`。当在正式作业中传入 `BASELINE_DIR`（含基线 `metrics.json`）时，会自动调用 `experiments/t3_visual_ref/compare_t32_runs.py` 在 `<out>/compare/` 下产出 `compare.md`、`compare.json` 与含 Top-5 涨跌样本错漏对比图及回放跳转的离线 `compare.html`。

回放由现有 demo_g3 渲染器生成，沿用点击切步、左右键、图像放大和掩码对比。青蓝参考图和两期查询图位于输入面板。隐藏类名、来源和空真值标记在「事后揭晓」中展示。32 题页面位于 `outputs/t3_visual_ref/t32_dev32/replay/`。demo_g3 目录通过保留相对路径的链接新增五张代表卡片，选非空 GT 的两个高分会话、一个有部分召回且 F1 最接近 0.5 的会话和两个低分会话。高分优先选模型主动提交。低分同分时优先展示不同虚警表现。最终分数和选样标签以实跑结果为准。

## Slurm 入口

数据准备使用 `python -m cd_agent.t32_dev32 prepare --manifest "$MANIFEST" --out outputs/t3_visual_ref/t32_dev32`，在 Slurm 计算节点执行并设置 `PYTHONPATH=src`。已有固定抽样清单可复用。

凭据由 `run_with_bailian_csv.py` 读取。作业将 endpoint 显式设为 `https://dashscope.aliyuncs.com/compatible-mode/v1`，并清除继承的代理环境变量。从仓库根目录提交，使用通过该公共端点直连预检的同一节点。SAM3 首次加载有 10 分钟就绪窗口。首先用 `smoke` 跑一题并校验 SAM3、Planner 和 Verifier，再以 `formal` 运行 Dev-32。正式作业串联推理、离线计分、回放生成和目录并入，支持跳过已有完整预测。

```bash
sbatch --nodelist="$NODE" --output="$PWD/.runtime/smoke/smoke-%j.log" \
  experiments/t3_visual_ref/run_t32_dev32.sbatch smoke
sbatch --nodelist="$NODE" --output="$PWD/outputs/t3_visual_ref/t32_dev32/logs/slurm-%j.log" \
  experiments/t3_visual_ref/run_t32_dev32.sbatch formal
```

提交环境传入已有 `BAILIAN_CSV` 路径。首次提交前创建上述日志目录。后续作业默认申请单 GPU、4 核和 9 GiB 内存。首次 Dev-32 正式作业 191004 申请了 16 GiB，Slurm 记录的峰值为 3.76 GiB。该轮冒烟作业的峰值为 6.87 GiB。冒烟确认真实模型与工具链可运行并落盘预测，步数耗尽等任务结果按 Harness 原始状态记录。作业结束时将 Slurm 内存统计写入 `logs/memory-<JobID>.log`。正式作业结束后检查 `metrics.json` 的 32 条结果、5 条选样、32 条回放与 demo_g3 链接，并对正式 Job ID 注册 exp-loop 完成通知。
